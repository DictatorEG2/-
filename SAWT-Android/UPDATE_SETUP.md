# إعداد التحديثات التلقائية — صَوْت

## آلية العمل
1. عند تشغيل التطبيق، يفحص GitHub Releases بعد مرور 24 ساعة على آخر فحص ناجح (ويعيد المحاولة بعد ساعة عند الفشل).
2. يقارن Tag الإصدار المنشور برقم `versionName` المثبّت.
3. إذا وجد إصدارًا أحدث، يظهر إشعار يفتح شاشة إعدادات التحديث.
4. يمكن للمستخدم بدء تنزيل APK من شاشة «إعدادات الصوت والتعرف».
5. يستخدم التنزيل Android DownloadManager، ثم يظهر إشعار عند اكتماله.
6. يفتح الإشعار مثبت Android. قد يطلب النظام السماح بتثبيت التطبيقات من صَوْت، ثم يعرض شاشة تأكيد التثبيت.

لا يوجد تثبيت صامت ولا حاجة إلى خادم خاص أو GitHub Token.

## إعداد المستودع
في `app/src/main/java/com/sawt/voice/update/UpdateConfig.kt` اضبط:

```kotlin
const val REPOSITORY = "OWNER/REPOSITORY"
```

القيمة الحالية `DictatorEG-coder/SAWT-Android` افتراضية، ويجب التأكد من تطابقها مع المستودع الحقيقي قبل النشر.

## نشر إصدار
1. ارفع مشروع Android إلى المستودع العام المحدد أعلاه.
2. ارفع APK إصدار Release موقّعًا.
3. أنشئ GitHub Release جديدًا بوسم إصدار رقمي مثل `v0.2.0`.
4. أرفق APK واحدًا عامًا ينتهي اسمه بـ `.apk` في Assets.
5. ارفع `versionName` داخل `app/build.gradle.kts` إلى نفس رقم الوسم، وارفع `versionCode` إلى رقم أعلى من كل إصدار سابق.
6. احتفظ بملف keystore وبياناته خارج GitHub والمشروع المضغوط. كل إصدار لاحق يجب أن يوقّع بالمفتاح نفسه.

## متطلبات التوقيع
- لا تضع keystore أو كلمات مروره أو GitHub Secrets داخل المستودع أو APK.
- لا يمكن تثبيت تحديث موقّع بمفتاح مختلف فوق النسخة الحالية؛ سيمنع Android ذلك.
- لا تُنشئ مفتاحًا جديدًا لكل إصدار. احتفظ بنسخة احتياطية آمنة من المفتاح الأصلي.

## حدود معروفة
- الفحص التلقائي يحدث عند فتح التطبيق، وليس عبر خدمة تعمل طوال الوقت.
- الفحص التلقائي محدود بمرة كل 24 ساعة؛ ويمكن للمستخدم الفحص يدويًا.
- التثبيت يحتاج تفاعل المستخدم وموافقة Android.
- إذا لم يوجد Release أو APK في المستودع، تظهر رسالة فشل/لا يوجد ملف صالح.
- القيمة الحالية للمستودع افتراضية حتى تأكيد اسم المستودع الحقيقي.
- يجب اختبار تنزيل وتثبيت إصدار تجريبي على جهاز فعلي قبل الإعلان عن جاهزية التحديثات.
