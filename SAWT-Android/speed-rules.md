# تطبيق قواعد الأداء والثبات

## القواعد الخمس
| القاعدة | التطبيق في الكود |
|---|---|
| فهرسة أعمدة البحث المتكرر | فهرسة أعمدة البحث والترتيب المتكرر ومراجعة أثر الفهارس. |
| منع N+1 | استخدام JOIN أو استعلامات مجمعة/دفعات عند وجود علاقات. |
| تجنب SELECT * | تحديد الأعمدة المطلوبة صراحةً. |
| Pagination | 20 عنصرًا للصفحة مع «تحميل المزيد»، باستثناء القوائم الصغيرة الثابتة مع توثيق السبب. |
| Cache | تخزين البيانات الثابتة نسبيًا مؤقتًا مع سياسة إبطال واضحة. |

## الثبات وجودة التسليم
- تجنب العمل الثقيل على Main Thread ومراقبة الذاكرة والبطارية والشبكة.
- مراجعة الأخطاء والحالات الحدية قبل وبعد كل تعديل.
- إزالة التكرار والكود الميت والاستيرادات غير المستخدمة دون حذف سلوك قائم.
- الحفاظ على بنية المشروع وعدم إعادة الكتابة الواسعة بلا ضرورة.
- عدم كسر ميزة سليمة عند إضافة ميزة جديدة، وإضافة اختبارات انحدار مناسبة.
- تشغيل اختبارات الوحدات والبناء عند توفر البيئة، وتوثيق ما لم يُنفَّذ صراحة.
- لا يُعلن إصدار مستقر لمجرد نجاح الفحص الساكن.

## التحديثات والأمان
- GitHub Releases العام مصدر التحديثات؛ لا خادم خاص ولا GitHub Token داخل APK.
- توقيع كل تحديث بالمفتاح نفسه، وحفظ keystore خارج المستودع.
- تحديث versionCode وversionName قبل النشر.
- لا تثبيت صامت؛ موافقة Android والمستخدم مطلوبة.

مرجعية إلزامية: `DICTATOR_STANDARDS.md`.
