# تطبيق قواعد الأداء والثبات

## القواعد الخمس
| القاعدة | التطبيق في الكود |
|---|---|
| 1. فهرسة أعمدة البحث المتكرر | `history(createdAt)` فهرس (كل الاستعلامات تُرتَّب به). `shortcuts(phrase)` فهرس **فريد** (يُبحث به عند كل أمر). انظر `data/Database.kt`. |
| 2. منع N+1 بـ JOIN أو استعلامات مجمّعة | لا توجد علاقات بين الجداول حاليًا، وكل شاشة تُحمَّل باستعلام واحد (صفحة سجل = استعلام واحد، العدّاد = استعلام واحد). عند إضافة جدول مرتبط يجب استخدام JOIN لا حلقة استعلامات. |
| 3. تجنب `SELECT *` | كل الاستعلامات تسمّي أعمدتها صراحة (`SELECT id, createdAt, utterance, …`) و`COUNT(id)` للعدّ. |
| 4. ترقيم القوائم بـ 20 عنصرًا مع Load More | `AppConfig.HISTORY_PAGE_SIZE = 20` مع `LIMIT/OFFSET`، وزر «عرض المزيد» في **سجل الأوامر** و**الاختصارات**. مكتبة الأوامر قائمة ثابتة صغيرة (13 مجموعة) في الذاكرة، فلا ترقيم لها. |
| 5. تخزين البيانات الثابتة نسبيًا مؤقتًا | `AppResolver`: قائمة التطبيقات المثبتة في ذاكرة لمدة 5 دقائق. `ShortcutRepository`: ذاكرة (مع تخزين سلبي) تُفرَّغ عند التعديل. الإعدادات في `StateFlow`. |

## الثبات
| الجانب | التنفيذ |
|---|---|
| معالجة الاستثناءات | `try/catch` حول التنفيذ والسجل والإطلاق والنوافذ العائمة، مع تسجيل تقني في `ErrorLog`. |
| دورة حياة الخدمات | `ListeningService` تنظّف الكوروتين والمحرك في `onDestroy`، و`SawtAccessibilityService` تزيل النوافذ وتلغي الكوروتين في `onUnbind/onDestroy`. |
| جلسة استماع واحدة | `VoiceController.isActive` + `AtomicBoolean` في الخدمة؛ أي طلب بدء ثانٍ يُتجاهل. |
| منع تكرار الأمر | نافذة ثانيتين لنفس النص المطبَّع (`AppConfig.DEDUP_WINDOW_MS`). |
| انقطاع محرك الصوت | `SpeechOutcome.Retry` مع تراجع تدريجي حتى 5 محاولات، و`withTimeoutOrNull(25s)`، وإعادة إنشاء المحرك عند `ERROR_CLIENT/BUSY/SERVER_DISCONNECTED`. |
| رفض الصلاحيات | تحقق قبل البدء، رسالة واضحة في الحالة، وتحويل لشاشة الأذونات. |
| البطارية والذاكرة | إيقاف تلقائي بعد الخمول، حركة الزر العائم تعمل أثناء الاستماع فقط، لا خدمات خلفية دائمة، حدود عمق/عدد عند قراءة شجرة الشاشة. |
| سجل أخطاء | ملف محلي ≤ 100KB بلا صوت ولا نص منطوق ولا محتوى شاشة. |
| الاختبارات | `ArabicNormalizerTest`، `ArabicCommandParserTest` (لم تُنفَّذ في بيئة الإنشاء، راجع `TESTING.md`). |


## مراجعة الكود وجودة التسليم
- مراجعة التغييرات قبل وبعد كل مهمة، مع البحث عن أخطاء المنطق والحالات الحدية.
- إزالة التكرار والأكواد الميتة والاستيرادات غير المستخدمة دون حذف سلوك مستخدم.
- الحفاظ على أسلوب المشروع وبنيته؛ لا إعادة كتابة أو تقسيم مفرط بلا سبب.
- فحص الصلاحيات والاعتماديات ومصادر الشبكة والتخزين.
- تشغيل اختبارات الوحدات والبناء عندما تتوفر البيئة، وتوثيق ما لم يُنفَّذ صراحة.
- لا يُعلن إصدار مستقر لمجرد أن الكود يبدو صحيحًا أو لأن الفحوصات الثابتة نجحت.

## التحديثات
- مصدر الإصدارات GitHub Releases العام المحدد في `UpdateConfig.kt`.
- لا أسرار أو GitHub Tokens داخل التطبيق.
- لا تثبيت صامت؛ Android يتولى موافقة المستخدم.
- يلزم استخدام مفتاح التوقيع نفسه لكل تحديث، وتحديث `versionCode` و`versionName` قبل النشر.


## مرجعية الثوابت
تُعد هذه القواعد جزءًا من معيار `DICTATOR_STANDARDS.md`، وتُراجع عند كل تعديل. لا تُستثنى قائمة من قاعدة الصفحات إلا إذا كانت صغيرة وثابتة بطبيعتها، مع توثيق السبب.
